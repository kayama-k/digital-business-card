# デジタル名刺アプリ 要件定義

更新日：2026-09-21
ステータス：公開名刺は確定事項を反映済み。名刺ビジュアルエディターは暫定要件として検討中。

## 1. 目的

交流会などでQRコードから開ける、個人用の縦型デジタル名刺を提供する。閲覧者がプロフィールとポートフォリオを心地よく確認でき、名刺の所有者は将来的にブラウザ上のビジュアルエディターで内容と演出を更新できるようにする。

## 2. 利用者と利用場面

| 利用者 | 主な利用場面 | 主な操作 |
| --- | --- | --- |
| 名刺の閲覧者 | QRコードやURLから名刺を開く | プロフィール・ポートフォリオの閲覧、保存、共有、QRコードの利用 |
| 名刺の編集者 | PCまたはスマートフォンのブラウザから名刺を更新する | 内容・素材・動きの編集、リアルタイムプレビュー、下書き保存、公開 |

## 3. 技術方針（確定）

| 層 | 採用技術 | 役割 |
| --- | --- | --- |
| フロントエンド | React、TypeScript、Vite、CSS | 公開名刺、編集画面、プレビュー、画面遷移とアニメーション |
| バックエンド | サポート中のJava LTS、Spring Boot | REST API、認証・認可、公開状態の制御、画像・名刺データの管理 |
| 永続化 | PostgreSQL、Spring Data JPA、Flyway | 名刺・編集設定・公開状態の保存、スキーマ変更の管理 |
| API契約 | OpenAPI | フロントエンドとバックエンド間の入出力を明文化する |

- CSSは通常のCSSとCSS変数を基本とし、Tailwind CSSは採用しない。
- フロントエンドをGitHub Pagesで公開する場合、Java APIとPostgreSQLは別の実行環境に配置する。
- APIの接続先は環境変数で管理し、秘密情報をフロントエンドへ含めない。

## 4. 公開名刺の機能要件（確定）

### 4.1 表示

- ログイン不要で閲覧できる、モバイル優先の縦型デジタル名刺を提供する。
- プロフィールとポートフォリオを切り替えられる。
- 名刺アプリへの入口QRコードと、ポートフォリオへのQRコードを各URL設定値から生成する。
- タイトルはSVGアウトライン素材を使用し、適切な代替テキストを提供する。
- 画像素材は、定めたアセットのパスを差し替えて更新できる。

### 4.2 保存・共有

- 保存・共有操作は別画面へ遷移せず、ボトムシートとして表示する。
- PNGは`1024 × 1536px`で保存できる。
- PDFは同じ保存用デザインを、1ページ・2:3比率で保存できる。
- Web Share APIが利用できない場合は、公開URLをコピーする代替手段を提供する。

### 4.3 画面遷移と波形

- プロフィールとポートフォリオの切替時のみ、横方向の画面遷移と青い波形を同時に開始する。
- 保存・共有のボトムシート表示時には波を動かさない。
- 波形は一度だけ動き、開始・終了の基準形状を同一にする。
- 基準値は、全体時間1.3秒、振幅19（SVG viewBox基準）、長い減衰、ゆっくり始まりゆっくり終わるイージングとする。
- OSまたはブラウザの`prefers-reduced-motion`を尊重する。

詳細は[animation-spec.md](animation-spec.md)を正とする。

## 5. 名刺ビジュアルエディター（暫定要件）

### 5.1 利用環境と共通要件

- 編集者は認証後、PC・スマートフォン双方のブラウザからエディターを利用できる。
- 編集、プレビュー、下書き保存、公開の全操作は両デバイスで完結できる。
- 編集内容は、スマートフォン幅の公開名刺プレビューへリアルタイムに反映する。
- PCでは編集項目とプレビューを並べて表示できる。スマートフォンでは編集項目をボトムシートまたはアコーディオンに収め、プレビューとの切替または連続表示を可能にする。
- ドラッグ操作を補助機能とし、スマートフォンではタップ可能な上下移動など、すべての操作に代替手段を用意する。

### 5.2 編集対象

- 名前、肩書き、自己紹介、所在地、リンク、SNS、ポートフォリオ情報
- プロフィール画像、タイトル素材、紙テクスチャなどの画像素材
- 配色、文字サイズ、余白、各要素の表示・非表示
- 公開状態（下書き、公開、公開停止）

### 5.3 アニメーション編集

- 利用者は、アニメーションを「なし」「やさしい波」「標準の波」「はっきりした波」など、視覚的なプリセットから選択できる。
- 選択したプリセットは、波の振幅、時間、減衰、イージングの設定値を一括で反映する。
- 詳細設定では、振幅、時間、減衰、イージングを個別に設定できる。個別変更後は状態を「カスタム」として扱う。
- 値には適切な上下限を設け、極端な動きや長すぎる遷移を防止する。
- プリセットまたは詳細値を変更すると、プレビューへ即時に反映できる。利用者が任意のタイミングで再生できるプレビューボタンも用意する。
- 選択中の設定が生む効果を、自然言語で表示する。例：振幅には「波の上下の揺れが自然に分かる強さ」、時間には「短いほど軽快、長いほどゆったりした印象」と表示する。
- 設定値の組合せから、現在の動きの要約を表示する。例：「現在の動き：やさしく、ゆったりした波。画面切替に合わせて穏やかに揺れ、約1.3秒で静止します」。
- `prefers-reduced-motion`が有効な利用者には、公開画面で動きを抑えることを明示する。

## 6. データと公開の考え方（暫定）

- 名刺の文言、URL、素材参照、配色、レイアウト、アニメーション設定、公開状態を名刺単位で保存する。
- 公開名刺は公開済みの設定のみを参照する。下書きは閲覧者に公開しない。
- フロントエンドはAPI通信を`api/`層に集約し、UIコンポーネントから直接HTTP通信を行わない。
- API仕様はOpenAPIで管理し、フロントエンドが使用する型との不整合を防ぐ。

## 7. 非機能要件

- モバイル優先かつPCでも操作しやすいレスポンシブデザインとする。
- キーボード操作、フォーカス表示、適切な代替テキスト、動きの抑制設定を考慮する。
- 画像アップロード、認証情報、APIの秘密情報を安全に扱う。秘密情報はクライアントへ配布しない。
- Java API導入後は、未認証者が編集・公開操作を行えないよう認可を実装する。

## 8. 保留事項

| 項目 | 現在の状態 | 次に決める内容 |
| --- | --- | --- |
| 紙テクスチャ | Figmaで使用中の画像を正式素材にする方針。書き出すレイヤーは未決定。 | 正式レイヤー、形式、配置パス、差し替え方針 |
| 認証方式 | 編集者の認証が必要。具体方式は未決定。 | 利用者数、ログイン方法、セッションまたはトークンの方式 |
| エディターのレイアウト自由度 | 配色・余白・表示制御は対象。自由配置の必要性は未決定。 | テンプレート選択型にするか、要素を自由配置できるようにするか |
| 画像保存先 | 将来は画像管理が必要。 | 保存容量、運用費、外部ストレージの採用 |
| 公開基盤 | フロントとJava APIの分離は可能。 | GitHub Pages継続の可否と、API・DBの配置先 |
